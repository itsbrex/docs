This policy covers the REQUEST BOT plugin, its MCP service and these public information pages. Brian Roach publishes REQUEST BOT.

What the plugin processes

When a host calls the service, it sends the arguments for that tool. These can include the request, optional owner and deadline, source labels or links, specialist drafts and open questions. Typeahead searches send the entered role query. The service uses these inputs to assemble, validate and display the requested work.

Processing and retention

The application processes work in memory during a call. It does not maintain a database of requests, log prompt bodies or fetch the source links you supply. Its per-instance traffic limiter holds a hashed network identifier for up to one minute, with expiry checked on later requests or instance shutdown. The returned board is part of the host conversation. Use the host’s conversation and data controls to manage that copy.

Service providers

The service runs on Vercel. Hosting providers can process technical data such as IP addresses, request time, route, status and failure diagnostics. GitHub serves these information pages and records visitor IP addresses for operational and security purposes. Infrastructure retention follows the provider’s applicable settings and policies. The application does not install advertising trackers or sell request data.

Support correspondence

If you email support, the publisher and the email service receive your address and message. Support mail may be kept while resolving and following up on the request. To ask about access or deletion, email hi@itsbrex.dev. You can also remove the plugin and manage conversation history through your chat host.
